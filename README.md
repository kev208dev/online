# ONLINE

성심당 지점의 기다림을 주변 로컬 상권 탐색으로 연결하는 단일 iPhone 체험용 MVP입니다. Expo 58, React Native, TypeScript, Expo Router를 사용합니다.

## 실행

Node.js 24, Xcode, iOS 17 이상이 필요합니다.

```bash
npm install
npm test
npm run typecheck
npm run lint
npx expo run:ios --device <UDID> --configuration Release --no-bundler
```

지도를 포함한 네이티브 기능은 Expo Go가 아닌 빌드된 앱에서 확인합니다. iOS 지도는 `expo-maps` Apple Maps입니다. iOS 17에서는 지도 이동·확대와 지점 선택 목록을 제공하고, iOS 18 이상에서는 마커 탭 선택도 지원합니다. 확인된 성심당 건물 좌표만 마커에 사용하며, 주변 가게의 불확실한 좌표는 핀으로 표시하지 않습니다.

## 앱 내 흐름

1. 네 지점 중 하나를 선택하고 앱 안에서 줄서기를 시작합니다. 대기시간 입력이나 실제 매장 줄서기 연동은 없습니다.
2. 선택 지점의 주변 가게를 보고 방문 일정에 담습니다. 실제 줄선 지점과 탐색 중인 지점은 별도 상태입니다.
3. 줄서기 중 외출 가능을 현장에서 확인한 경우에만 해당 지점의 앱 내 방문 쿠폰을 발급합니다. 확정된 제휴 할인은 없으며, 쿠폰에는 실제 할인 혜택이 없습니다.
4. 매장용 화면에서 지점별 전체 인원을 관리하고 `앞사람 처리`를 누르면 이 기기의 개인 앞사람 수가 줄어듭니다. 관리자 PIN을 통과해야 이 작업 및 QR 인증이 가능합니다.
5. 앞사람 수가 0명이 되면 입장 QR이 보입니다. 관리자 화면에서 카메라 스캔 또는 수동 코드 입력으로 입장·쿠폰을 각각 1회 인증합니다.

## 저장과 권한

`src/domain/queue.ts`와 `src/domain/commerce.ts`는 순수 상태 전이를, `src/state/queueRepository.ts`는 저장소 인터페이스와 AsyncStorage 구현을 담당합니다. 지점별 `queueCount`, `nextTicketNumber`, 개인 `peopleAhead`는 독립적입니다. 전체 인원 수정은 이미 발급된 번호나 앞사람 수를 조정하지 않습니다. 기존 버전의 시간 기반 대기는 활성 큐로 복원하지 않습니다.

관리자 초기 설정은 일반 매장 화면과 분리되어 있습니다. 운영자가 정한 설정 코드의 SHA-256 검증값을 Git에 넣지 않는 `.env.local`의 `EXPO_PUBLIC_ADMIN_SETUP_VERIFIER`에 넣어야 PIN을 처음 설정할 수 있습니다. 해시 입력은 `online-setup-v1:` 뒤에 설정 코드를 붙인 문자열입니다. PIN 검증값은 난수 salt와 함께 `expo-secure-store`의 기기 전용 Keychain에 저장됩니다. 앱 재실행·백그라운드 진입 또는 PIN 오류 후에는 잠깁니다. PIN 설정 후 설정 코드는 재사용할 수 없습니다.

이 방식은 **시연용 접근 제한**입니다. 짧은 설정 코드의 빌드 내 검증값은 역추측될 수 있고, 앱 내 PIN은 실제 서버 기반 매장 권한 인증이 아닙니다.

## 구현 범위와 다음 단계

대기·쿠폰·인증 기록은 한 기기 내부에만 있습니다. 다른 기기의 실시간 대기 순번, 중앙 서버 동기화, 실제 성심당의 입장 QR 확인, 실제 제휴 쿠폰 사용, 결제 연동은 지원하지 않습니다. 로컬 알림은 이 기기에서 관리자가 앞사람을 처리한 순간에만 발생할 수 있으며, 실제 매장 호출을 감지하지 않습니다. 주변 가게의 위치·영업 여부·도보 시간은 방문 전 재확인이 필요합니다.

실서비스에는 매장 운영자 인증, 서버의 원자적 번호 발급·쿠폰 소비, 지점별 실시간 데이터, 상점 제휴 검증, 앵커 매장 웨이팅 시스템 협력이 필요합니다.
