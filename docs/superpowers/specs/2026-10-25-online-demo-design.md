# ONLINE 시연용 MVP 구현 명세
작성: 2026-10-25 · 상태: 사용자 확인 전

## 목적과 범위
“기다림을 지역 상권의 새로운 소비 기회로 전환한다.”
성심당 본점 주변 대전 은행동 상권을 대상으로, 소비자의 수동 대기시간 등록부터 주변 매장 발견, 방문 일정, 쿠폰 발급·인증, 복귀 안내까지 연결한다.
기존 Expo 58 / React Native / TypeScript / Expo Router 앱을 확장한다. 실제 앵커 매장의 웨이팅 접수·순번 변경·입장 인증은 하지 않는다.

## 사용자 요청으로 확정된 사항
- 사용자가 앱에서 앵커 매장을 선택하고 예상 대기시간을 직접 입력한다.
- 현장 줄 이탈 시 순번을 잃는 경우 외출을 추천하지 않는다.
- 홈은 발견·추천, 일정은 선택한 방문 예정 매장의 순서·예상 시간·복귀 시간 관리에 집중한다.
- 소비자가 쿠폰 QR을 제시하고 제휴 매장이 확인하여 사용 처리한다. 중복 사용을 막는다.
- 할인 정책·로그인·서버·지도 제공사는 미정이다.
- 시연용으로 끝까지 작동하는 앱이 목표다.
- 기존 Figma 디자인의 주황색, 사진·아이콘, Pretendard 서체, 화면 분위기를 이어가되 반응형 배치를 적극 개선한다.
- iOS Liquid Glass 하단 바를 유지한다. 홈·검색·일정·설정을 모두 작동시킨다.

## 이번 구현에 제안하는 기본값 — 승인 대상
1. 로그인·서버 없이 기기에 저장하는 단일 기기 데모로 먼저 완성한다. 소비자와 매장 화면을 같은 앱에서 전환한다. 다른 기기와 실시간 공유하거나 실제 결제에 사용할 수 있다고 표시하지 않는다.
2. 모든 혜택은 “시연용 혜택”으로 표시한다. 실재 매장의 제휴·할인 제공을 주장하지 않는다. 기존 디자인의 할인 문구는 시연 데이터로만 재사용한다.
3. 쿠폰은 대기 기록 1회당 매장별 1장, 1회 사용, 해당 예상 대기 종료 시각까지 유효하다. 발급 당시 혜택 조건을 저장하여 이후 매장 편집으로 기존 쿠폰 조건이 변하지 않는다.
4. 복귀 여유는 5분으로 시작한다. 이동·체류 시간은 시연용 추정치이며 실시간 보행 경로나 GPS 측정치가 아니다.
5. 초기 앵커 선택지는 성심당 본점 1곳이다. 현장 운영 정책을 확인했다고 가정하지 않는다. 사용자가 “줄을 떠나도 되는지 확인했어요”를 직접 선택하지 않으면 외출 추천·방문 일정 추가·쿠폰 발급을 막는다.
6. 내장 지도는 기존 지도 이미지를 명확히 표시한 시연용 지도로 사용하고 매장 상세와 연결한다. 실제 위치 확인은 외부 국내 지도 검색으로 연결한다. 카카오/네이버 SDK를 통한 실시간 지도는 API 키와 제공사 결정 후 별도 단계다.

## 화면과 동작
### 홈 / 대기 등록
- 첫 실행은 대기 미등록 화면: 서비스 가치 설명, 앵커 선택, 예상 시간 입력.
- 시작 버튼은 “대기시간 기록 시작”. 실제 매장 웨이팅 접수가 아니라는 안내를 함께 보여 준다.
- 활성 상태에는 수동 입력 기준 남은 시간, 예상 종료 시각, 복귀 안내를 표시한다.
- 기존의 가상 순번·대기 번호·입장 QR·순번 미루기는 제거한다.
- 기록 종료는 앱 내 기록만 끝낸다. 실제 매장의 대기는 취소되지 않음을 안내한다.
- 외출 확인과 충분한 시간이 있을 때만 시간에 맞는 주변 매장을 추천한다. 시간이 부족하거나 외출 불가이면 이유와 현장 대기 안내를 제공한다.

### 검색 / 매장 상세
- 매장명 검색, 카테고리, 거리순·이름순 정렬, 시연용 지도/목록.
- 매장 사진·분류·주소·정보 확인 상태·예상 이동/체류 시간·시연 혜택.
- 정확하지 않은 메뉴·가격·영업시간은 만들어 넣지 않는다. 필요한 시연 메뉴는 시연 데이터임을 명시한다.
- 일정 담기/제거, 쿠폰 발급, 국내 지도에서 검색.
- 중복된 아저씨 돈까스 항목과 잘못된 카테고리는 정리한다.
- 대기시간 초과, 외출 불가, 혜택 비활성화, 이미 발급됨 등을 각각 설명한다.

### 일정
- 저장한 매장의 방문 순서, 예상 체류·이동 시간, 앵커 복귀 예상 시각.
- 추가는 검색·상세에서, 제거·순서 변경·방문 완료 표시는 일정에서 한다.
- 여러 매장 간 이동은 실제 경로처럼 보이지 않도록 보수적인 시연 추정 방식으로 계산하고 명시한다.
- 전체 일정이 남은 대기시간에 맞지 않으면 경고하고 무리한 추가를 차단한다. 시간이 흐르며 초과하면 기존 계획은 보존하고 복귀를 권한다.
- 선택한 현재 방문 매장 기준으로 복귀 시간과 알림 시각을 갱신한다. GPS 자동 감지는 하지 않는다.

### 쿠폰함 / 매장 시연
- 쿠폰마다 고유 식별자를 인코딩한 QR을 실제 생성한다. 기존 공통 QR 이미지는 인증에 쓰지 않는다.
- 발급·사용·만료 상태, 발급 당시 조건과 시간 이력을 보존한다.
- 매장 화면에서 매장을 선택하고 해당 매장의 쿠폰만 인증한다.
- 동일 기기 시연은 발급된 쿠폰 선택 또는 코드 입력으로 인증 전체 과정을 확인한다.
- 카메라 QR 스캔도 지원한다. 동일 기기에 저장된 쿠폰 코드를 다른 화면에 띄워 스캔할 수 있다. 다른 설치에서 발급한 코드는 공유 서버가 없어 인증되지 않음을 안내한다.
- 유효하지 않음·다른 매장·이미 사용·만료 상태를 구분하고, 연속 스캔/중복 클릭도 한 번만 처리한다.
- 매장별 시연 혜택 문구·조건·활성 상태 편집, 발급/사용 이력 조회.
- 통계는 이 기기에서 기록한 쿠폰 사용 건수만 보여 준다. 실제 매출/지역경제 효과를 조작하지 않는다.

### 복귀 안내 / 설정
- 종료 전 복귀 권고 시각에 앱 내 안내와 선택적 기기 로컬 알림을 제공한다.
- 알림 권한은 사용자가 켤 때 요청하고 거절 시 앱 내 안내가 유지됨을 설명한다.
- 알림은 매장 호출이 아니라 수동 예상시간 기준이다. 앱이 백그라운드에 있어도 예약된 로컬 알림이 동작하도록 한다.
- 일정·대기 기록 변경/종료 시 이전 예약을 취소·갱신한다.
- 예상시간 경과 후 “매장 현장에서 순서를 확인하세요”로 전환하며 입장이 확정됐다고 하지 않는다.
- 설정에서 쿠폰함, 매장 시연, 알림 상태, 시연 정책, 확인 후 데모 데이터 초기화.
- 대기·일정·쿠폰·혜택 편집을 저장하고 앱 재실행 시 복원한다. 초기화는 앱 데모 데이터와 관련 알림만 제거한다.

## 기술 선택과 후속 확장
이번에는 기존 Expo 프로젝트에 필요한 저장·QR·카메라·로컬 알림 모듈만 추가한다. 모듈 버전은 Expo 58 호환성에 맞춘다.
대기·일정·쿠폰 검증을 화면과 분리하여 자동 테스트 가능한 순수 함수로 구현한다.
실서비스 권장 구조는 기존 모바일 앱 + TypeScript API + PostgreSQL이다. 매장 계정/권한과 쿠폰 사용 처리는 서버에서 검증하고 단일 트랜잭션으로 중복 사용을 막아야 한다. 이는 후속 제안이며 이번에 서버를 배포하거나 외부 계정을 만들지 않는다.
카카오/네이버 지도는 현장 위치 데이터·키·이용조건·비용을 확인해 선택한다. 이번 시연에 유료 API나 외부 로그인 설정을 요구하지 않는다.

## 검증과 완료 조건
- 등록 전 → 외출 허용 여부 확인 → 수동 대기 시작 → 추천 → 상세 → 일정 → 쿠폰 발급 → 매장 인증 → 중복 거절 → 복귀 안내를 끝까지 확인.
- 외출 불가, 부족한 시간, 만료 쿠폰, 다른 매장, 앱 재실행, 권한 거절을 검증.
- 대기·일정·쿠폰 규칙 자동 테스트, lint, TypeScript 검사, iOS Release 빌드.
- 연결된 iPhone에 설치·실행하고 주요 화면을 확인. 잠금·권한 등 사용자 조작이 필요한 경우에만 요청.
- 실제 제휴·지도 정확도·다른 기기 QR 인증·매장 호출·매출 효과를 구현한 것으로 오인시키지 않는다.
- GitHub push 및 스토어 배포는 이번 범위에 포함하지 않는다.

## 현재 확인이 필요한 제약
Figma 연결이 재인증을 요구하여 이번 턴에는 원본 프레임을 읽지 못했다. 원본 충실도 확인은 연결 복구 후 진행한다. 기존 코드/에셋만으로 원본 검증을 완료했다고 하지 않는다.
