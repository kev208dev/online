# ONLINE 지점별 줄서기·지도 개편

## 목적

기다리는 고객을 주변 로컬 상점으로 연결하되, 앱을 열자마자 앵커 매장을 찾고 줄서기·쿠폰·입장 인증까지 자연스럽게 이어지게 한다. 사용자가 직접 대기시간을 입력하는 흐름은 제거한다. 첨부된 기능 1(앵커 탐색/웨이팅 등록), 기능 2(주변 가게 탐색/쿠폰), 기능 3(대기 종료/입장 QR)를 모두 작동시킨다.

## 사용자 확정 사항

- 현재 제품 범위는 단일 iPhone의 체험용 MVP다. 중앙 서버·다중 사용자 실시간 동기화·실매장 QR 인증은 제공하지 않는다. 내부 구현 문서에도 이 경계를 명시한다.
- 성심당 여러 지점을 선택해 줄선다. 지점별 현재 대기 인원은 우선 앱 안의 매장용 화면에서 관리한다. 외부 웨이팅 시스템은 없다.
- 지점마다 주변 로컬 상점을 제공한다. 본점뿐 아니라 대전역점, DCC점, 롯데백화점 대전점에도 실제 위치를 확인한 가게를 연결한다.
- 전체 대기 인원 수동 수정은 개별 사용자의 순번·앞사람 수를 바꾸지 않는다. 앞사람 수는 매장용 `앞사람 처리` 또는 앞선 대기자의 취소·이탈에서만 감소한다. 전체 인원이 내 번호보다 작아져도 자동 보정하지 않는다.
- 매장용 인원 관리·QR 인증에는 관리자 PIN을 둔다.
- 대기 종료 QR은 우선 앱 안의 매장용 화면에서 인증한다. 서로 다른 기기의 데이터 동기화는 없다.
- 대기시간 기록·직접 입력 기능을 삭제한다. 시연을 강조하는 설명과 불필요한 장문 문구를 UI에서 제거하되 작은 `체험용` 표시는 유지한다.
- 손가락으로 이동·확대·축소되는 지도를 제공한다. 홈 화면과 하단 내비게이션의 겹침을 없앤다.
- 기존 Figma의 큰 사진, 주황색 포인트, 흰 화면, Pretendard, 매장/대기 숫자 카드, 주변 가게 목록 및 iOS Liquid Glass 하단 바를 우선한다. 없는 기능에 필요한 최소한의 선택·인증 UI만 추가한다.

## 범위와 설계 선택

- 앵커 선택지: 성심당 본점, 대전역점, DCC점, 롯데백화점 대전점. 명칭·주소는 성심당 공식 사이트 기준. 지점 위치는 지도 검색 자료로 좌표를 확인해 마커로 표시한다.
- iOS 지도는 Expo 58의 `expo-maps` Apple Maps를 사용한다. 핀치·드래그·마커 탭·화면의 확대/축소 버튼을 지원한다. 네이티브 지도가 불가능한 환경에는 기존 이미지가 아니라 지점 목록을 우선 제공한다. Android 실지도는 API 키 확보 후 연결한다.
- 새 설치의 지점별 앱 내 대기 인원은 0명이다. 매장용 화면에서 수를 입력/조정할 수 있다. `queueCount`, `nextTicketNumber`, 개인 `peopleAhead`를 독립적으로 저장한다. 고객 줄서기는 그 시점 `queueCount`를 앞사람 수로 기록하고 지점별 `nextTicketNumber`로 고유 번호를 발급한 뒤 두 지점별 카운터를 각각 한 번 갱신한다. 관리자의 전체 수 수동 변경은 기존·미래 번호 카운터와 기존 개인 앞사람 수를 변경하지 않는다. UI에는 작은 `체험용` 표시를 제공한다.
- 한 기기에서 활성 줄서기는 하나다. 매장용 `앞사람 처리`는 해당 지점의 전체 인원과 내 앞사람 수를 각각 한 명씩 줄인다. 인원 수동 수정은 전체 수만 바꾸고 순번·앞사람 수는 그대로 둔다. 내 앞사람 수가 0이 되면 한 번만 쓸 수 있는 입장 QR이 표시된다. 같은 지점의 매장용 스캔/코드 입력으로 인증할 때만 줄서기 완료로 바뀐다. 다른 지점·중복 인증은 거절한다.
- 매장용 진입은 별도 초기 설정 흐름에서 관리자 PIN을 만든 다음 PIN 확인을 거친다. 사용자가 정한 1회 설정 코드는 Git에 넣지 않고 빌드 전용 로컬 환경 설정의 검증 해시로 주입한다. 설정 완료 후에는 다시 사용할 수 없다. PIN 검증 정보는 AsyncStorage가 아닌 iOS Keychain 기반 보호 로컬 저장소에 둔다. PIN 오류·재실행 뒤에는 잠금 상태를 유지한다. 초기 설정 화면을 일반 고객용 매장 화면과 분리한다. PIN은 시연용 접근 제한이며 서버 권한 인증이 아니다. PIN 분실 시 보호 저장소의 관리자 자격을 재설정해야 한다.
- 선택 중인 지도 지점과 실제 줄선 지점은 다른 상태값이다. 지도 지점 전환은 기존 줄서기를 취소하거나 등록 지점을 변경하지 않는다.
- 도메인은 저장 API를 직접 호출하지 않는다. 저장소 인터페이스를 통해 기기 내 구현을 연결하여 나중에 서버 저장소로 교체할 수 있게 한다.
- 줄을 이탈하면 순번을 잃을 수 있으므로, 고객이 `외출 가능`을 확인하기 전에는 주변 방문 일정과 쿠폰 발급을 권하지 않는다.
- 은행동 기존 가게는 본점에 연결한다. 다른 세 지점에도 공개된 위치를 확인한 주변 가게를 최소 2곳씩 넣는다. 위치·도보거리·사진을 확인할 수 없는 경우에는 임의 좌표나 타 지점 사진을 붙이지 않는다. 매장별 쿠폰은 앱 안에서만 발행·관리되는 혜택이며 실제 매장 제휴·할인을 주장하지 않는다.
- 예상 대기 종료 시각을 만들지 않는다. 일정은 방문 순서·도보 거리·체류시간을 보여 주고, 내 앞사람이 3명 이하가 되면 복귀를 권한다. 인원 수만으로 입장 시각을 확정할 수 없으므로 시간 카운트다운/정확한 복귀 시각은 표시하지 않는다. 로컬 알림은 앱 내 순서 변경이 관측될 때만 보내고, 백그라운드 원격 호출을 약속하지 않는다.
- 쿠폰은 활성 줄서기 중 해당 등록 지점의 주변 가게에만 발급 가능하고 매장당 1회, 발급 후 1회 사용한다. 줄서기 종료 시 미사용 쿠폰은 종료한다. 실제 제휴가 확인되지 않은 할인율/무료 제공을 확정 혜택으로 표시하지 않는다. UI에는 긴 시연 문구 대신 작은 `체험용`·`앱 내 쿠폰`만 둔다.
- 기존 v1 저장 상태는 읽되 과거의 수동 대기시간 기록은 활성 줄서기로 이전하지 않는다. 쿠폰 사용 이력과 매장 편집 내용은 가능한 범위에서 보존한다.

## 화면 흐름

1. **홈/앵커 탐색**: 지점 지도·지점 목록에서 선택. 선택 지점의 사진(기존 자산이 있으면 사용), 이름, 주소, 앱 내 대기 인원을 보여 주고 `줄서기`를 누른다. 활성 줄서기 중에는 등록 지점을 분명히 표시하고 Figma의 사진 → 매장 정보 → 나의 순서 카드 → 로컬 추천 순서로 구성한다. 선택만 다른 지점으로 바꿔도 활성 줄서기는 그대로 유지된다.
2. **주변 탐색/쿠폰**: 지도에서 손가락 확대·축소/드래그, 마커 선택과 목록/상세 이동. 선택한 네 지점 모두의 주변 가게 상세에서 방문 일정에 담고 쿠폰을 발급한다. 쿠폰 QR은 PIN을 통과한 매장용 화면에서 같은 기기 데이터로 인증하고 중복 사용을 차단한다.
3. **대기 종료/입장 QR**: 매장용 화면에서 앞사람 처리 또는 인원 조정. 내 앞사람 수가 0이면 홈에 입장 QR이 나타난다. PIN 잠금을 푼 매장용 화면에서 같은 기기의 QR을 스캔하거나 코드를 수동 입력해 인증한다. 매장용 인증 후 상태는 `입장 완료`로 바뀌고 같은 QR 재사용은 불가하다. 다른 기기와 실시간 인증은 지원하지 않는다.
4. **일정/설정**: 일정은 선택한 매장 순서·방문 상태와 현재 내 앞사람 수를 간결히 표시한다. 설정에서 쿠폰함, 매장용 관리, 알림, 앱 데이터 초기화를 열 수 있다. 장문의 시연/면책 카드와 대기시간 입력 UI는 없다.

## 정확성·안전성

- 공식 현장 순번·실시간 대기 인원·제휴 할인이라고 허위 표시하지 않는다. 앱 내 수치와 인증은 해당 기기에만 저장된다. 관리자 PIN은 기기 내 관리 화면 접근만 보호하며 기기 소유자·서버 권한 인증이 아니다.
- 지점별로 큐 인원을 분리한다. 활성 줄서기 중 다른 지점으로 중복 접수되지 않는다.
- 다른 지점 QR, 미호출 QR, 이미 인증한 QR, 만료된 쿠폰은 거부한다. 빠른 연속 입력에도 1회만 성공한다.
- 전체 인원을 내 발급 번호보다 낮게 설정한 뒤에도 번호·앞사람 수는 그대로다. `앞사람 처리`를 반복해도 `peopleAhead`는 음수가 되지 않는다.
- 지도 위치가 확인되지 않은 가게에는 핀을 임의로 만들지 않는다.

## 검증

- 줄서기 시작 → 인원/순번 확인 → 앞사람 처리 → 입장 QR → 인증 → 중복 거절을 순수 도메인 테스트와 실기기에서 확인한다.
- 지점별 인원·다음 번호 분리, 수동 인원 수정 후 번호 일관성, 중복 줄서기, 잘못된 지점 QR, 쿠폰 중복/만료, 재실행 복원, 관리자 PIN 잠금, 하단 바 겹침, 지도 핀치/줌 버튼을 확인한다.
- TypeScript, lint, 자동 테스트, iOS Release 빌드와 연결된 iPhone 설치·실행을 확인한다. GitHub push는 하지 않는다.

## 디자인 제약

원본 Figma 파일의 모바일 프레임(홈 `142:365`, 지도 `88:121`, 주변 가게 `178:1137`, 상세 `151:613`, 쿠폰 QR `169:882`, 입장 QR `169:776`)을 2026-10-25에 직접 대조했다. 홈은 전폭 매장 사진 → 이름·주소 → 흰색 테두리의 2열 숫자 카드 → 로컬 가게 목록, 검색은 상단 지도 → 둥근 흰색 바텀 시트 → 지점·로컬 가게 목록, 상세는 전폭 사진 → 매장 정보 → 쿠폰 카드 → 지도 → 하단 주황색 행동 버튼을 따른다. 사진·간격·타이포·주황색을 우선 보존하며 화면 크기 대응과 Liquid Glass 하단 바는 iOS에 맞춰 조정한다. 원본의 예상 대기시간·웨이팅 미루기처럼 현재 범위와 충돌하는 부분만 앞사람 수·입장 QR로 교체한다.
