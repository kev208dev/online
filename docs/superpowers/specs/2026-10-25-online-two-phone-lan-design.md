# ONLINE 두 iPhone LAN 연동 설계

## 목적과 범위

같은 장소에서 고객폰과 매장폰으로 실제로 연결되는 촬영 흐름을 만든다. Mac을 켜 둔 채 두 iPhone을 같은 Wi‑Fi에 연결한다. 기존 앱을 두 폰에 설치하고 고객폰에서 줄서기·쿠폰 QR을 만들면 매장폰에서 앞사람 처리·QR 또는 수동 코드 인증을 수행한다. 화면은 Figma의 홈·검색·상세·하단 바를 유지한다.

이는 공식 성심당 웨이팅이나 로컬 상점 시스템과 연동하지 않는다. 한 촬영 세션에는 고객폰 한 대와 매장폰 한 대만 참여한다. 여러 고객의 실제 동시 접수, 인터넷 너머 접속, Mac 없이 작동, 백그라운드 푸시, 실매장 할인은 이번 범위 밖이다. 앱 화면의 `체험용` 문구는 사용하지 않지만, 쿠폰에는 `실제 할인 없음`을 유지한다.

## 동작

1. Mac에서 프로젝트의 Node 서버를 실행하면 LAN 접속 주소, 고객 연결 코드, 매장 관리자 연결 코드가 표시된다. 코드는 짧게 만료되고 최초 연결 후 소비된다. 두 코드는 다르다. 서버 상태는 Mac의 Git 무시 파일에 저장되며 재시작 후 복구된다.
   촬영 중 폰을 교체하거나 코드를 잃으면 Mac 명령으로 해당 역할의 연결 코드만 재발급할 수 있고, 기존 줄서기·쿠폰 기록은 유지한다. 새 테이크를 시작할 때만 별도 Mac 명령으로 기록 전체를 명시적으로 초기화한다. 전체 초기화는 기존 연결 토큰도 무효화하고 새 코드를 발급한다. 재발급과 초기화는 자동으로 서로를 호출하지 않는다.
2. 두 폰의 설정 화면에서 Mac 주소를 입력하고 각자의 연결 코드를 넣는다. 기존 기기 내 데이터는 지우거나 공유 서버에 자동 병합하지 않는다. 공유 서버 연결을 끄면 기존 로컬 데이터로 돌아간다. 공유 모드에서는 서버가 순번·인원·쿠폰·사용 여부의 유일한 원본이다.
3. 고객폰은 네 지점 중 하나를 선택하고 필수 이용 제한 동의에 체크한 뒤 줄선다. 체크 전에는 줄서기 버튼을 사용할 수 없다. 동의 체크는 이 앱 안에서 주변 방문·쿠폰도 허용한다는 사용자 결정에 따라 `leaveAllowed`로 저장한다. 이는 실제 매장의 이탈 허용 여부를 검증한 것은 아니다. 등록 직후 `줄서기` 탭에 대기번호와 앞사람 수가 표시된다. 매장폰에서 해당 지점의 전체 인원을 조정하거나 `앞사람 처리`를 누르면 고객폰에 약 1초 이내 반영된다. 인원 수동 변경은 기존 고객의 번호와 앞사람 수를 바꾸지 않는다.
4. 고객폰은 등록 지점 주변 가게 상세에서 바로 앱 내 쿠폰을 발급받는다. 방문 일정 저장 기능은 없다. 매장폰은 가게를 선택해 고객폰 QR을 스캔하거나 코드를 입력하여 쿠폰을 한 번만 사용 처리한다. 앞사람 수가 0명이 되면 고객폰에 입장 QR이 표시되고, 매장폰은 해당 지점 코드로 한 번만 입장 인증한다. 양쪽 화면에 사용·완료 상태가 동기화된다.
5. 네트워크가 끊기면 공유 모드 화면에 `연결 끊김`을 보이고 변경 동작을 막는다. 로컬 저장 상태에 대신 쓰지 않는다. 다시 연결되면 Mac 서버 상태를 새로 받아 표시한다.

## 구현 선택

- 기존 Expo 58 앱, 순수 큐/쿠폰 도메인 함수, iOS 관리자 PIN 잠금, QR UI를 재사용한다. 서버는 Node의 HTTP API와 1초 간격 동기화를 사용한다. 영상 촬영 중 두 앱은 전경 실행을 전제로 한다. 별도 클라우드 계정이나 외부 데이터베이스는 추가하지 않는다.
- 서버는 지점별 `queueCount`·`nextTicketNumber`, 고객 한 명의 활성 대기, 발급·사용 쿠폰, 소비된 입장 코드를 소유한다. 고객의 지도 선택 지점과 폰의 화면 상태는 기기별 로컬 상태로 남긴다. 한 요청에서 상태 검증·변경·저장을 완료한 뒤 응답하여 두 폰에서 같은 코드를 연속 인증해도 한 번만 성공한다.
- 매장 변경 API는 Mac 서버가 발급한 관리자 세션 토큰을 요구한다. 매장폰의 기존 로컬 PIN도 잠금 해제해야 화면을 사용할 수 있다. PIN 자체를 서버에 보내거나 Git에 넣지 않는다. 고객 연결은 별도 세션 토큰을 받는다. 토큰은 폰의 보호 저장소에 넣고 서버 코드·토큰은 콘솔에 다시 노출하지 않는다.
- LAN의 HTTP 연결 및 짧은 페어링 코드는 촬영용 접근 제한일 뿐 운영 환경의 보안 인증이 아니다. 공개 Wi‑Fi나 실제 개인정보·결제정보에는 사용하지 않는다. 앱과 안내문은 공식 웨이팅·확정 제휴 할인이라고 표현하지 않는다.
- 줄서기 전 홈·검색 화면에 다음 문구를 그대로 보여 준다. 마지막 동의 문장은 검은색 밑줄을 적용하고, 미동의 시 줄서기 버튼은 비활성화한다. 이 문구는 사용자 안내·동의만 다루며 이번 범위에서 실제 이용 제한 기간이나 자동 제재는 구현하지 않는다.

- iOS 로컬 네트워크 접근에 필요한 Expo 설정만 추가한다. 주소와 상태는 설정에 간결히 표시하고 기존 Figma UI는 유지한다. Mac IP가 바뀌면 설정에서 다시 연결한다.

## 데이터 보존과 실패 처리

- 기존 단일 기기 기록은 지우지 않는다. 공유 서버 모드로 바꿀 때 이전 대기를 자동 등록하지 않으며, 사용자가 새 촬영 세션에서 줄서기를 시작한다.
- 서버 저장 파일은 원자적으로 교체해 재시작 시 반쯤 기록된 상태를 읽지 않는다. 잘못된 지점·쿠폰·코드·권한, 만료 코드, 재사용 코드는 명확한 오류로 응답한다. 관리자 수동 인원 변경은 개별 `peopleAhead`에 영향을 주지 않는다.
- 코드만 재발급할 때 이전에 연결된 폰의 토큰은 그 역할에서 무효화한다. 큐·쿠폰은 그대로 유지한다. 전체 초기화는 큐·쿠폰·사용 이력과 양쪽 토큰을 함께 비운다. 두 명령 모두 Mac 콘솔에서만 실행하며 대상 역할과 초기화 범위를 명확히 확인한다.
- 서버가 꺼졌거나 폰이 다른 Wi‑Fi에 있으면 연결 실패를 알려 준다. 재연결 뒤에는 서버 값으로 갱신한다. 이 설계는 한 명의 고객을 대상으로 하므로 다른 고객폰의 동시 줄서기는 명시적으로 거절한다.

## 검증 완료 조건

- 서버 단위 테스트에서 고객/매장 두 독립 클라이언트로 등록 → 앞사람 처리 → 입장 QR 인증 → 중복 거절과 쿠폰 발급 → 매장 인증 → 중복 거절을 확인한다. 지점별 번호, 수동 인원 변경, 서버 재시작 복구, 잘못된 권한, 연결 끊김 시 변경 거부도 확인한다.
- 연결 코드 재발급 뒤 옛 토큰이 거부되고 기존 큐·쿠폰이 남는지, 전체 초기화 뒤 옛 토큰과 기록이 함께 사라지는지 확인한다.
- `npm test`, TypeScript 검사, lint, iOS Release 빌드를 통과한다. 연결된 iPhone 두 대가 실제로 준비되면 양쪽에 설치하여 지도·줄서기·쿠폰·QR 스캔·수동 코드 입력과 약 1초 동기화를 확인한다. 두 번째 기기가 없다면 실기기 2대 연동은 미검증으로 보고한다.
- GitHub push는 별도 요청 전까지 하지 않는다.

## 구현자가 정할 부분

정확한 HTTP 경로와 메시지 형식, 저장 파일 스키마, 네트워크 재시도 간격의 세부값, 설정 화면의 배치, 서버 시작 명령은 기존 프로젝트 구조에 맞춰 정한다. 고객/매장 연결 코드는 충분한 난수로 만들고 인증 실패 시 정보를 새지 않게 처리한다.
